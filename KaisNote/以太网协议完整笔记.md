## 以太网基础概念

### 什么是以太网？
**以太网（Ethernet）** 是目前最广泛使用的局域网技术标准，定义了网络设备之间的物理连接和数据传输规则。

### 核心特征
- 🌐 **CSMA/CD** - 载波侦听多路访问/冲突检测
- 📏 **帧格式** - 标准化的数据帧结构
- 🏷️ **MAC地址** - 物理地址标识
- ⚡ **速率** - 10Mbps到400Gbps不等

### MAC地址详解

**MAC地址格式：** `XX:XX:XX:XX:XX:XX`
- 📏 **长度**：48位（6字节）
- 🏭 **OUI**：前24位为厂商标识
- 🔢 **设备标识**：后24位为设备唯一标识
- 🌍 **全球唯一**：理论上每个网卡都有唯一MAC地址

**示例：**
```
00:1B:44:11:3A:B7
│  │  │  │  │  │
│  │  │  └──┴──┴── 设备标识 (24位)
└──┴──┴────────── OUI厂商标识 (24位)
```

## 传输层协议

### TCP vs UDP 对比

```plantuml
@startuml
!theme plain
skinparam backgroundColor white

package "传输层协议对比" {
  class "TCP" {
    + 面向连接
    + 可靠传输
    + 流量控制
    + 拥塞控制
    + 数据单元: Segment
    + 头部: 20-60字节
  }
  
  class "UDP" {
    + 无连接
    + 不可靠传输
    + 无流量控制
    + 无拥塞控制  
    + 数据单元: Datagram
    + 头部: 8字节
  }
}

note right of TCP : 适用于文件传输、网页浏览
note right of UDP : 适用于视频直播、在线游戏
@enduml
```

### TCP段结构详解

**为什么TCP使用Segment而不是Packet？**

1. **语义准确性**：
   - Segment = 数据流的片段
   - Packet = 独立的数据包

2. **功能特性**：
   ```plantuml
   @startuml
   !theme plain
   
   participant "应用层" as App
   participant "TCP层" as TCP  
   participant "IP层" as IP
   participant "以太网层" as Eth
   
   App -> TCP: 大数据流
   TCP -> TCP: 分割成Segments
   TCP -> IP: TCP Segment
   IP -> IP: 封装成IP Packet
   IP -> Eth: IP Packet
   Eth -> Eth: 封装成Ethernet Frame
   @enduml
   ```

3. **TCP段特点**：
   - 🔢 **序列号** - 保证顺序
   - ✅ **确认号** - 保证可靠性
   - 🪟 **窗口大小** - 流量控制
   - 🔄 **重传机制** - 错误恢复

## 地址解析协议

### ARP vs NDP 详细对比

```plantuml
@startuml
!theme plain
skinparam backgroundColor white

package "地址解析协议" {
  class "ARP (IPv4)" {
    + IP地址 → MAC地址
    + 广播请求
    + 单播响应
    + 无安全机制
    + 独立协议
  }
  
  class "NDP (IPv6)" {
    + IPv6地址 → MAC地址
    + 邻居发现
    + 路由器发现
    + 地址自动配置
    + 基于ICMPv6
    + 支持安全扩展
  }
}

ARP --> "IPv4网络" : 服务于
NDP --> "IPv6网络" : 服务于

note bottom of ARP : 仅地址解析功能
note bottom of NDP : 多功能邻居管理
@enduml
```

### ARP工作流程

```plantuml
@startuml
!theme plain

participant "主机A\n192.168.1.10" as HostA
participant "交换机" as Switch  
participant "主机B\n192.168.1.20" as HostB
participant "主机C\n192.168.1.30" as HostC

HostA -> Switch: ARP请求广播\n"谁有192.168.1.20?"
Switch -> HostB: 转发ARP请求
Switch -> HostC: 转发ARP请求

HostB -> Switch: ARP响应\n"我是192.168.1.20\nMAC: BB:BB:BB:BB:BB:BB"
Switch -> HostA: 转发ARP响应

note right of HostA : 更新ARP缓存表\n192.168.1.20 → BB:BB:BB:BB:BB:BB
@enduml
```

## 数据传输流程

### 完整通信流程示例

**场景：** 主机A (192.168.1.10) 访问网站 (www.example.com)

```plantuml
@startuml
!theme plain

participant "主机A" as HostA
participant "路由器" as Router
participant "DNS服务器" as DNS  
participant "Web服务器" as WebServer

== 1. DNS解析 ==
HostA -> DNS: DNS查询 www.example.com
DNS -> HostA: 返回IP地址 93.184.216.34

== 2. ARP解析网关MAC ==
HostA -> Router: ARP请求网关MAC地址
Router -> HostA: ARP响应网关MAC地址

== 3. TCP连接建立 ==
HostA -> WebServer: SYN (通过路由器转发)
WebServer -> HostA: SYN-ACK
HostA -> WebServer: ACK

== 4. HTTP请求 ==
HostA -> WebServer: HTTP GET请求
WebServer -> HostA: HTTP响应

== 5. 连接关闭 ==
HostA -> WebServer: FIN
WebServer -> HostA: ACK + FIN  
HostA -> WebServer: ACK
@enduml
```

## 重要概念总结

### 数据单元命名规则

| 层次 | 数据单元名称 | 英文术语 | 特点 |
|------|-------------|----------|------|
| 应用层 | 消息 | Message | 应用程序间的完整信息 |
| 传输层 | 段/数据报 | Segment/Datagram | TCP用Segment，UDP用Datagram |
| 网络层 | 数据包 | Packet | 包含路由信息的数据单元 |
| 数据链路层 | 帧 | Frame | 包含物理地址的数据单元 |
| 物理层 | 比特 | Bit | 最基本的数据单位 |

### 地址类型对比

| 地址类型 | 长度 | 作用范围 | 示例 | 用途 |
|----------|------|----------|------|------|
| MAC地址 | 48位 | 局域网内 | 00:1B:44:11:3A:B7 | 数据链路层寻址 |
| IPv4地址 | 32位 | 全球 | 192.168.1.1 | 网络层路由 |
| IPv6地址 | 128位 | 全球 | 2001:db8::1 | 网络层路由 |
| 端口号 | 16位 | 主机内 | 80, 443 | 传输层进程标识 |

### 协议特点速查

```plantuml
@startuml
!theme plain
skinparam backgroundColor white

map "协议特点对比" {
  TCP => 可靠、有序、面向连接、开销大
  UDP => 快速、简单、无连接、开销小  
  IPv4 => 32位地址、使用ARP、广泛部署
  IPv6 => 128位地址、使用NDP、安全性强
  ARP => IPv4专用、广播请求、无安全
  NDP => IPv6专用、多播请求、可加密
  Ethernet => 局域网标准、CSMA/CD、帧结构
}
@enduml
```

## 实际应用场景

### 常见网络应用的协议选择

| 应用类型 | 传输层协议 | 原因 |
|----------|------------|------|
| 网页浏览 | TCP | 需要可靠传输，确保页面完整 |
| 文件下载 | TCP | 必须保证文件完整性 |
| 视频直播 | UDP | 实时性要求高，偶尔丢包可接受 |
| 在线游戏 | UDP | 延迟敏感，需要快速响应 |
| 邮件发送 | TCP | 邮件内容不能丢失 |
| DNS查询 | UDP | 查询简单，快速响应 |

### 网络故障排查思路

```plantuml

  :检查网络层;

  :检查ARP表、路由表;

  :检查防火墙、服务状态;
```
