# Rtm

## 模块描述

Runtime Measurement.
Rtm allows the user to determine runtimes and CPU load of BSW modules and user code sections.
Measurement is controlled- and evaluated in CANoe by RTM's frontend or a self-written RTM
application. Data exchange between CANoe and the ECU is done by the XCP protocol.
#AMD #Xcp #CANoe #CANape #Monitoring #RuntimeMeasurement
#Vector

### 2. RtmMeasurementPoint

**描述**: Each measurement point describes one code area whose runtime shall be measured using the RTM module.

#### 参数列表

```yaml
- 
  序号: 1
  名称: RtmAutostartEnabled
  长名称: ''
  描述: |
    Defines if this measurement shall be activated during ECU startup automatically.
    
    Autostart may be used for init-functions which are called only during the startup-phase the
    communication stack, XCP and RTM module are activated.
    
    Note: Each autostart measurement causes CPU-load. It is therefore advised to activate autostart
    only when it is required.
    
  默认值: false
  最小值: ''
  最大值: ''
- 
  序号: 2
  名称: RtmMeasurementEnabled
  长名称: ''
  描述: This parameter defines the availability of a measurement section during pre-compile time. If
      disabled, the measurement points of this section will be generated as empty macros.
      Hence this measurement section requires no memory- or runtime resources. Since the
      measurement settings are still part of the ECU configuration, the measurement enabled
      settings can be changed later.
  默认值: true
  最小值: ''
  最大值: ''
- 
  序号: 3
  名称: RtmMeasurementGroup
  长名称: ''
  描述: |
    The name can be used to organize measurement sections into groups by defining a unique group
    name. The groups will be visible in CANoe and the generated measurement report.
    
  默认值: ''

  最大值: ''
- 
  序号: 4
  名称: RtmDisableInterrupts

    Defines if interrupts are locked during measurement.
    
    If enabled, RTM locks interrupts during measurement using the critical section
    RTM_EXCLUSIVE_AREA_0. This results in more accurate measurement results but will increase the
    time spent with locked interrupt.
    
  默认值: false
  最小值: ''
  最大值: ''
- 
  序号: 5
  名称: RtmMeasurementId
  长名称: ''
  描述: This ID defines the measurement object
  默认值: 0

-

    If set to GrossExecutionTime:

    If set to NetExecutionTime:
      - Measures like GrossExecutionTime  minus interruptions by task or ISR.
    If set to FlatExecutionTime:
      - Measures like NetExecutionTime minus the execution time of nested measurement points.
  默认值: GrossExecutionTime
  最小值: ''
  最大值: ''
- 
  序号: 7
  名称: RtmMeasurementPointType
  长名称: ''

    This parameter defines whether the measurement point measures:

  最小值: ''
```

### 3. RtmCoreDefinition

**描述**: Each Measurement Point needs to have a core description assigned. The core description defines on
which core the Measurement Point is running on. There is a special case when no
/MICROSAR/Rtm/RtmCoreDefinition/RtmCore is configured. This is for cross core applications where a
measurement is started on one core and stopped on another core.

#### 参数列表

```yaml
- 
  序号: 1
  名称: RtmCoreDefinitionId
  长名称: ''
  描述: Symbolic Name Value of this container.
  默认值: 0
  最小值: 0
  最大值: 65535
- 
  序号: 2
  名称: RtmNumberOfTaskResponseTimePercentiles
  长名称: ''
  描述: |
    When this feature is enabled (value > 0) a percentile histogram is calculated and managed by the
    RTM. The histogram is divided in as many divisions as here configured exclusively the additional
    200% percentile.
    Example: If this parameter is set to 2, there is the 0-99%, the 100-199%, and the 200%
    percentiles.
    Please note: This feature requires additional runtime and memory. The histogram can be persisted
    in NvM.
    
    If this parameter does not exist, this feature is disabled.
  默认值: 10
  最小值: 2
  最大值: 255
- 
  序号: 3
  名称: RtmCore
  长名称: ''
  描述: |
    Defines the core the application is running on. For cross core measurement, leave this field
    empty.
    
  默认值: 0
  最小值: 0
  最大值: 65535
- 
  序号: 4
  名称: RtmBSWCore
  长名称: ''
  描述: This parameter defines whether this Core is running the BSW software. Only one Core Definition
      can have this flag set.
  默认值: false
  最小值: ''
  最大值: ''
- 
  序号: 5
  名称: RtmBackgroundTaskName
  长名称: ''
  描述: |
    Name of the background/idle task of this core.
    This parameter is only required for CPU load measurement.
    
    Per default, the IdleTask_OsCore<CoreId> is the correct background/idle task, but it is possible
    to cover this task by a custom background/idle task implementing an endless loop. As this task
    has a higher priority, the IdleTask_OsCore<CoreId> will never be called. Therefore, the custom
    background/idle task shall be set here.
  默认值: ''
  最小值: ''
  最大值: ''
```

#### 参数列表

```yaml
- 
  序号: 1
  名称: RtmHyperperiod
  长名称: ''
  描述: Defines the time frame of the histogram information. Needs to be a multiple of the Rtm

  长名称: ''

    For this feature a measurement point called "Rtm_CpuLoadMeasurement" (resp. in multi core

    Please note that this measurement point(s) should not be called by an application.
  默认值: C_API
  最小值: ''
  最大值: ''
- 
  序号: 3
  名称: RtmNumberOfCpuLoadPercentiles
  长名称: ''
  描述: |
    When this feature is enabled (this parameter exists) a percentile histogram is calculated and
    managed by the RTM. The histogram is divided in as many divisions as here configured exclusively
    the additional 100% percentile.
    Example: If this parameter is set to 2, there is the 0-49%, the 50-99%, and the 100%
    percentiles.
    Please note: This feature requires additional runtime and memory. The histogram can be persisted
    in NvM.
    
    If this parameter does not exist, this feature is disabled.
  默认值: 10
  最小值: 2
  最大值: 99
```
